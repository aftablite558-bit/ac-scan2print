## 4. Hosting Architecture Audit & Deployment Gaps

Audit of Firebase project `aman-computer-27b21` and local hosting configurations:

### 4.1 Build Outputs
- **Admin Dashboard (`dist/`):** Built via `npm run build` (`vite build`). Root HTML `dist/index.html` (1.7 KB), assets bundle (`dist/assets/`). Passes `npm run lint`.
- **Customer Portal (`dist-customer/`):** Built via `npm run build:customer` (`vite build --config customer-portal/vite.config.ts`). Root HTML `dist-customer/index.html` (1.66 KB), assets bundle (`dist-customer/assets/index-*.js`, 570 KB). Passes `npm run lint:customer`.

### 4.2 Hosting Configuration Disconnect (Critical Deployment Gap)
1. **Root `firebase.json`:**
   ```json
   {
     "hosting": {
       "public": "dist",
       "rewrites": [{ "source": "**", "destination": "/index.html" }]
     }
   }
   ```
   Root configuration points solely to `dist` (Admin Dashboard). There are no multi-site target definitions.
2. **Customer Portal `customer-portal/firebase.json`:**
   ```json
   {
     "hosting": {
       "public": "../dist-customer",
       "rewrites": [{ "source": "**", "destination": "/index.html" }]
     }
   }
   ```
   Isolated configuration with `customer-portal/.firebaserc.example` containing placeholder `your-customer-portal-hosting-project-id`. No `.firebaserc` exists in the repository.
3. **Identified Hosting Gap:**
   If `firebase deploy` is executed from the repository root, **only the Admin Dashboard is deployed** to `https://ac-scan2print.web.app`. Any walk-in customer scanning the counter QR code pointing to `https://ac-scan2print.web.app/quick-print` will be rewritten to `/index.html` of the Admin Dashboard and presented with the Admin Login screen.
4. **Resolution Required in Phase 3 (Not Executed in Phase 0):**
   Configure Firebase Hosting multi-site targets in root `firebase.json` (e.g., target `admin` -> site `ac-scan2print`, target `customer` -> site `ac-scan2print-customer`), OR merge customer portal routes into a unified build output with path-based routing.

## 5. Confirmed Owner Decisions & Technical Boundaries

1. **Separation of Concerns:** AC Scan2Print uses a dedicated Supabase project (`tvtfgsijxlxpwgakpeag`) and Firebase project (`aman-computer-27b21`). No coupling to personal or legacy accounts.
2. **Strict Single-Admin Access:** Only the registered Super Admin account (`Yr0Wr7PuuAdOIMaqohmqaINNbNC2`) is authorized. Staff and operator sub-accounts are explicitly excluded from MVP scope.
3. **Optional Customer Identity:** Customer name and phone number remain optional; anonymous submissions authenticated via cryptographic tracking tokens are the primary path.
4. **UPI vs. Cash Invariants:**
   - UPI: Payment verification auto-qualifies approved jobs for the print queue without requiring a secondary manual approval step.
   - Cash: Requires explicit Admin confirmation (`admin-confirm-cash`) before queue release.
5. **Physical Sheet Duplex Billing:** Duplex rate is strictly billed per physical paper sheet (`ceil(pages / 2)`), never per page.
6. **No Native In-App Scanner:** Customers scan the counter QR poster using their smartphone's native camera or Google Lens. No in-app camera scanner is needed.
7. **Manual Release Protocol:** GitHub automated CI/CD deployment is intentionally disabled. All migrations, Edge Functions, and frontend bundles are reviewed and deployed manually.

## 6. Architectural Gaps & Production Risks Summary

1. **Unmapped Customer Portal Hosting:** `dist-customer/` is not linked to any active Firebase deploy target in root `firebase.json`.
2. **Empty Environment Files:** Local `.env.local` currently contains empty keys. Runtime relies on mock adapters unless real Supabase and Firebase keys are provided in deployment environments.
3. **Missing Windows Print Agent:** The entire physical printing pipeline (Phases 5–7) is unimplemented. Print jobs remain in database state `queued` until the Windows agent is written and paired with the counter PC.
4. **Hardware Discovery Incomplete:** Exact PC specs and printer models remain unrecorded (`NEEDS USER INPUT`).
5. **Physical Print Tests Pending:** All 13 physical print scenarios are unexecuted (`NOT VERIFIED`).
